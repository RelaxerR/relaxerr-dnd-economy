# Relaxerr — Экономика ДнД

Веб-сервис экономики для игроков кампании: каталог предметов с динамической ценой
(город/сезон/игровая сессия), заявки на добавление предметов, профиль игрока, админ-панель.

Статус: **Фазы 0-3 завершены**, из Фазы 4 готов rate limiting и деплой — сайт живёт на
[relaxerr-dnd-economy.ru](https://relaxerr-dnd-economy.ru) (Docker + автодеплой из `main` через
GitHub Actions, см. `docker-compose.prod.yml` и `.github/workflows/deploy.yml`). Не начата
только полировка визуального стиля. Подробный разбор всех архитектурных решений — в `CLAUDE.md`.

## Структура решения

```
src/
  DndEconomy.Domain          — сущности и enum'ы, без внешних зависимостей
  DndEconomy.Application     — бизнес-логика (расчёт цены, импорт), не знает про EF Core
  DndEconomy.Infrastructure  — EF Core, PostgreSQL, Identity, импорт Excel
  DndEconomy.Web             — Blazor Server, Program.cs, rate limiting
```

Расчёт цены (`PriceCalculationService`) — прямой перенос формул листа
"Текущая стоимость" исходной таблицы:

```
РассчитаннаяСтоимость = БазоваяСтоимость × КэфСессии × КэфГорода × КэфСезона
СтоимостьПродажи      = РассчитаннаяСтоимость × КэфПродажи (либо штрафной откуп, если нет в наличии)
```

Услуги (`Item.IsService`, например "Обмен валют") — исключение из этой формулы: вместо цены
показывается комиссия по городу (как это выглядит для игрока и как настраивается из админки —
см. раздел ["Приём монет и обмен валют"](#приём-монет-и-обмен-валют) ниже). Архитектурные
детали (почему у услуг умолчание CityModifier перевёрнуто по сравнению с товарами и т.п.) —
в `CLAUDE.md`.

Интеграция с Foundry VTT (макросы "узнать цену"/"создать предмет") авторизуется отдельным
статичным API-ключом (`X-Api-Key`), не cookie-сессией сайта — см. `foundry-macros/README.md`.

## Приём монет и обмен валют

Сайт не хранит и не двигает деньги персонажей — кошелёк живёт в Foundry VTT (поля
cp/sp/ep/gp/pp на листе персонажа). Эти два блока — чисто справочная информация по городу,
которую игрок сверяет вручную и сам переносит на свой лист.

### Что видит игрок

На странице каталога (`/catalog`), под строкой "Цены актуальны для города...", есть
разворачивающийся блок **«Приём монет в городе N»** — таблица по всем пяти номиналам
(медь/серебро/электрум/золото/платина) с одним из трёх статусов:

- **Принимается по номиналу** — меняют/принимают без потерь;
- **Со скидкой N%** — примут, но с потерей части номинала;
- **Отказывает** — этот номинал в городе не в ходу.

Под таблицей может быть заметка админа с нюансами, которые не сводятся к простому
номиналу — например, «золото принимают только через старосту» или «медь и серебро не
берут за товар дороже мелкого прайса».

Фиксированный курс между номиналами (100 медных = 10 серебряных = 2 электрума = 1 золотая =
1/10 платиновой) — это правило самой игры, оно не меняется по городам и не настраивается
из админки.

Услуга **"Обмен валют"** — это обычная запись в каталоге (её можно найти поиском или по
типу «Услуги»), но вместо цены покупки/продажи у неё показывается один из трёх статусов:

- **Без комиссии** — обменяют один в один;
- **Комиссия: N%** — обменяют, но заберут часть суммы;
- **Не оказывается в этом городе** — в городе нет пункта обмена (стандартно для деревень,
  кроме отдельных исключений вроде люкс-поселений).

Тот же принцип действует и в избранном на `/profile`, если добавить "Обмен валют" туда.

### Как настроить из админки

1. **Приём номиналов по городу** — страница `/admin/economy/coin-acceptance`: таблица
   номинал×город, в каждой ячейке — доля приёма (1 = без скидки, например 0.7 = скидка 30%,
   0 = отказ). Пустая ячейка = принимается по номиналу без скидки, отдельно заводить нужно
   только исключения. Под таблицей — текстовое поле заметки на каждый город (нюансы вроде
   "только через старосту").
2. **Услуга обмена валют**:
   - Завести саму запись на `/admin/items/new` — заполнить название (например, "Обмен
     валют"), Тип/Подтип (например, "Услуги" / "Обмен валют") и обязательно поставить
     галочку **"Это услуга, а не физический товар"**. Базовую стоимость и вес для услуги
     оставляют равными 0.
   - Задать комиссию по городам на уже существующей странице `/admin/economy/city-modifiers`
     — для Типа/Подтипа этой услуги завести коэффициент для каждого города, где обмен есть
     (например, 0.93 = комиссия 7%). **Важно**: в отличие от обычных товаров, для строк-услуг
     (они помечены бейджем «услуга» в таблице) пустая ячейка означает не "коэффициент 1",
     а "услуга здесь не оказывается" — включать обмен нужно явно в каждом городе, где он
     должен работать, а не выключать его в каждой деревне.

## Первый запуск локально

1. Поднять PostgreSQL, например через Docker:
   ```bash
   docker run --name dnd-economy-db -e POSTGRES_USER=dnd_economy \
     -e POSTGRES_PASSWORD=dev_password -e POSTGRES_DB=dnd_economy_dev \
     -p 5432:5432 -d postgres:16
   ```
2. Восстановить пакеты и установить `dotnet-ef`, если ещё не установлен:
   ```bash
   dotnet tool install --global dotnet-ef
   dotnet restore
   ```
3. Применить миграции (в репозитории уже есть пять — `InitialCreate`, `AddTrigramSearchIndexes`,
   `AddCyrillicCollationToItemName`, `AddSessionDisplayPin`, `AddCoinAcceptanceAndServiceItems`):
   ```bash
   dotnet ef database update -p src/DndEconomy.Infrastructure -s src/DndEconomy.Web
   ```
   Целевой Postgres должен быть собран с ICU (проверить: `SELECT collname FROM pg_collation
   WHERE collname = 'ru-x-icu';` должна вернуть строку) — без этого не применится миграция
   с кириллической коллацией для `Item.NameRu`.
4. Задать первого администратора через user-secrets (без этого при старте будет только
   предупреждение в лог — залогиниться будет некем):
   ```bash
   cd src/DndEconomy.Web
   dotnet user-secrets set "AdminSeed:Email" "admin@example.com"
   dotnet user-secrets set "AdminSeed:Password" "ВременныйПароль123!"
   ```
5. Запустить сайт:
   ```bash
   dotnet run --project src/DndEconomy.Web
   ```
   При первом старте с пустой БД в логе появится "Создан первый администратор" — войти
   под этим email/паролем, дальше приложение принудительно попросит сменить пароль
   (`MustChangePassword=true`), после чего откроется каталог (`/catalog`).
