# Relaxerr — Экономика ДнД

Веб-сервис экономики для игроков кампании: каталог предметов с динамической ценой
(город/сезон/игровая сессия), заявки на добавление предметов, профиль игрока, админ-панель.

Статус: **Фазы 0-3 завершены**, из Фазы 4 готов rate limiting и деплой — сайт живёт на
[relaxerr-dnd-economy.ru](https://relaxerr-dnd-economy.ru) (Docker + автодеплой из `main` через
GitHub Actions, см. `docker-compose.prod.yml` и `.github/workflows/deploy.yml`). Не начата
только полировка визуального стиля. Подробный разбор всех архитектурных решений — в `CLAUDE.md`.

## Структура решения

```
src/
  DndEconomy.Domain          — сущности и enum'ы, без внешних зависимостей
  DndEconomy.Application     — бизнес-логика (расчёт цены, импорт), не знает про EF Core
  DndEconomy.Infrastructure  — EF Core, PostgreSQL, Identity, импорт Excel
  DndEconomy.Web             — Blazor Server, Program.cs, rate limiting
```

Расчёт цены (`PriceCalculationService`) — прямой перенос формул листа
"Текущая стоимость" исходной таблицы:

```
РассчитаннаяСтоимость = БазоваяСтоимость × КэфСессии × КэфГорода × КэфСезона
СтоимостьПродажи      = РассчитаннаяСтоимость × КэфПродажи (либо штрафной откуп, если нет в наличии)
```

Услуги (`Item.IsService`, например "Обмен валют") — исключение из этой формулы: вместо цены
показывается комиссия по городу (подробнее — в разделе ["Как это работает"](#как-это-работает)
ниже). Архитектурные детали (почему у услуг умолчание CityModifier перевёрнуто по сравнению
с товарами и т.п.) — в `CLAUDE.md`.

## Как это работает

Ниже — по одному разделу на каждую страницу сайта: что на ней делает игрок и что настраивает
администратор. Технические детали реализации — в `CLAUDE.md`, здесь только "что видит
пользователь".

### Вход

Самостоятельной регистрации нет — доступ строго по приглашению. Администратор заводит
учётную запись на `/admin/users` (email, отображаемое имя, временный пароль, роль
Игрок/Администратор) и передаёт email/пароль игроку лично. При первом входе с временным
паролем сайт принудительно требует его сменить, прежде чем откроется что-либо ещё.

### Каталог (`/catalog`)

Главная страница игрока. Показывает предметы кампании с ценой, посчитанной для активной
на сегодня игровой сессии (её выбирает система — последняя сессия, чья реальная дата не
позже сегодняшней, либо принудительно закреплённая администратором; название сессии, город
и игровая дата видны в шапке страницы). Есть:

- **Поиск** — устойчивый к опечаткам (Postgres `pg_trgm`): "мечь" находит "Длинный меч".
- **Фильтры** — по категории (источник/книга правил), типу и подтипу предмета, галочка
  "только в наличии".
- **Сортировка** — по имени или по цене.
- Каждая карточка — цена покупки/продажи в монетах ДнД (авто-выбор самого крупного
  подходящего номинала — платина/золото/электрум/серебро/медь), бейдж "Добавлено
  сообществом" для предметов, заведённых из одобренных заявок игроков, и "Нет в наличии",
  если предмет не продаётся в этом городе/сезоне.
- Разворачивающийся блок **«Приём монет в городе N»** под шапкой — таблица по всем пяти
  номиналам (медь/серебро/электрум/золото/платина), у каждого один из трёх статусов:
  **Принимается по номиналу** / **Со скидкой N%** / **Отказывает**, плюс, если админ её
  оставил, свободная заметка с нюансами вроде «золото принимают только через старосту».
  Фиксированный курс между номиналами (100 медных = 10 серебряных = 2 электрума = 1 золотая
  = 1/10 платиновой) — правило самой игры, не меняется по городам. Сайт не хранит и не
  двигает деньги персонажей — кошелёк живёт в Foundry VTT (поля cp/sp/ep/gp/pp на листе
  персонажа), это только справочная информация, которую игрок сверяет вручную.
- Услуга **"Обмен валют"** — обычная запись в каталоге (тип «Услуги»), но вместо цены
  покупки/продажи у неё один из трёх статусов: **Без комиссии** / **Комиссия: N%** / **Не
  оказывается в этом городе** (стандартно для большинства деревень).

### Карточка предмета (`/catalog/{id}`)

Тот же набор данных, что и в карточке каталога, плюс кнопка **«Сохранить в избранное»**
(восковая печать) — добавляет предмет в профиль игрока.

### Профиль (`/profile`)

- **Избранное** — сохранённые предметы с актуальной ценой (или статусом комиссии, если это
  услуга), с собственным поиском по списку и кнопкой удаления.
- **Заявки на предметы** — форма "предложить предмет, которого нет в каталоге" (название +
  описание/контекст) и список своих заявок со статусом (на рассмотрении/одобрена/отклонена),
  вместе с комментарием администратора, если он есть.

### Уведомления (`/notifications`)

Приходят, когда администратор одобряет или отклоняет заявку игрока на предмет. Счётчик
непрочитанных виден в шапке сайта на каждой странице; live-обновления нет — счётчик
обновляется при переходе между страницами.

### Админ-панель

Все страницы под `/admin/*` требуют роль Администратор.

- **Пользователи** (`/admin/users`) — список всех аккаунтов, приглашение нового (email/имя/
  временный пароль/роль), удаление (кроме себя).
- **Заявки** (`/admin/requests`) — заявки игроков на рассмотрении: «Одобрить» открывает форму
  создания предмета (с предзаполненным названием) — после сохранения предмет попадает в
  каталог с бейджем "Добавлено сообществом"; «Отклонить» просто закрывает заявку.
- **Предметы** (`/admin/items`) — список всех предметов каталога с поиском (тот же
  опечатко-устойчивый поиск, что и в каталоге) и постраничным выводом по 20. Клик по строке
  открывает редактирование всех полей, есть удаление предмета. Здесь же — импорт/экспорт
  листа "Предметы" (см. ниже).
- **Новый предмет** (`/admin/items/new`) — ручное создание предмета каталога: категория, тип,
  подтип, название (рус./англ.), базовая стоимость, вес, и галочка **"Это услуга, а не
  физический товар"** для нефизических записей вроде "Обмен валют" (у них базовую стоимость
  и вес обычно оставляют нулевыми — вместо цены считается комиссия по городу).
- **Массовое изменение цен** (`/admin/items/bulk-price`) — пересчёт базовой стоимости у всех
  предметов в заданном ценовом диапазоне разом (прибавить/умножить/задать). Необратимо —
  страница требует сначала построить предпросмотр (старая и новая цена каждого предмета),
  и только потом подтвердить применение.
- **Города и сессии** (`/admin/economy/*`) — под общей вкладочной навигацией. На каждой из
  пяти страниц внизу — своя панель "Скачать текущее (.xlsx)" / загрузить файл: экспорт отдаёт
  только нужный лист, импорт из загруженного файла читает тоже только его, даже если в книге
  есть остальные листы (шаблоны — в `/templates`, один и тот же файл можно грузить на любую
  подходящую страницу). Повторная загрузка безопасна — записи обновляются по ключу, а не
  дублируются.
  - **Города** — список городов и добавление нового (название + категория поселения:
    деревня/город/крупный город — влияет на то, какой ассортимент товаров вообще доступен).
  - **Коэф. города** — матрица "Тип+Подтип товара × Город": множитель к базовой стоимости
    (0 = этот товар в этом городе не продаётся). Строки — все категории, которые реально
    встречаются у предметов каталога, появляются в таблице сами, заводить их вручную не
    нужно; коэффициенты, оставшиеся от категории, которой больше нет ни у одного предмета,
    помечаются и их можно удалить отдельной кнопкой. Тем же способом задаётся и комиссия
    услуги "Обмен валют" — только для строк-услуг (помечены бейджем «услуга») пустая ячейка
    означает не коэффициент 1, а "услуга здесь не оказывается" — её нужно явно включать в
    каждом городе, где она должна работать.
  - **Коэф. сезона** — та же идея (включая автоматические строки), но множитель зависит от
    сезона (весна/лето/осень/зима), а не от города.
  - **Приём монет** (`/admin/economy/coin-acceptance`) — матрица "Номинал × Город": доля
    приёма (1 = без скидки, например 0.7 = скидка 30%, 0 = отказ), плюс текстовая заметка с
    нюансами на каждый город. Пустая ячейка = принимается по номиналу без скидки — заводить
    нужно только исключения.
  - **Сессии** — "Партии" из исходной Excel-модели: реальная и игровая дата, город, сезон,
    коэффициент сессии и коэффициент скупки. Система сама показывает игрокам сессию с
    последней реальной датой не позже сегодня; кнопкой «Показывать эту» администратор может
    принудительно закрепить другую (например, подготовить цены следующей встречи заранее) —
    закрепление снимается автоматически, как только наступает дата более новой сессии.

### Интеграция с Foundry VTT

Макросы "узнать цену" и "создать предмет" (`foundry-macros/`) обращаются к сайту напрямую
из Foundry, минуя обычный вход — авторизуются статичным API-ключом в заголовке `X-Api-Key`
(отдельные ключи на поиск и на создание предметов), а не cookie-сессией сайта, чтобы вызов
макроса из вкладки Foundry не разлогинивал игрока на сайте в других вкладках браузера.
Подробности — в `foundry-macros/README.md`.

## Первый запуск локально

1. Поднять PostgreSQL, например через Docker:
   ```bash
   docker run --name dnd-economy-db -e POSTGRES_USER=dnd_economy \
     -e POSTGRES_PASSWORD=dev_password -e POSTGRES_DB=dnd_economy_dev \
     -p 5432:5432 -d postgres:16
   ```
2. Восстановить пакеты и установить `dotnet-ef`, если ещё не установлен:
   ```bash
   dotnet tool install --global dotnet-ef
   dotnet restore
   ```
3. Применить миграции (в репозитории уже есть пять — `InitialCreate`, `AddTrigramSearchIndexes`,
   `AddCyrillicCollationToItemName`, `AddSessionDisplayPin`, `AddCoinAcceptanceAndServiceItems`):
   ```bash
   dotnet ef database update -p src/DndEconomy.Infrastructure -s src/DndEconomy.Web
   ```
   Целевой Postgres должен быть собран с ICU (проверить: `SELECT collname FROM pg_collation
   WHERE collname = 'ru-x-icu';` должна вернуть строку) — без этого не применится миграция
   с кириллической коллацией для `Item.NameRu`.
4. Задать первого администратора через user-secrets (без этого при старте будет только
   предупреждение в лог — залогиниться будет некем):
   ```bash
   cd src/DndEconomy.Web
   dotnet user-secrets set "AdminSeed:Email" "admin@example.com"
   dotnet user-secrets set "AdminSeed:Password" "ВременныйПароль123!"
   ```
5. Запустить сайт:
   ```bash
   dotnet run --project src/DndEconomy.Web
   ```
   При первом старте с пустой БД в логе появится "Создан первый администратор" — войти
   под этим email/паролем, дальше приложение принудительно попросит сменить пароль
   (`MustChangePassword=true`), после чего откроется каталог (`/catalog`).

## Разбор музыки

Администратору доступна вкладка **Музыка**. Приложение случайно выбирает трек из исходного
каталога, перекодирует его для прослушивания в Opus 128 кбит/с и позволяет обрезать,
переименовать и назначить несколько папок. При сохранении итоговый файл помещается в
`<DestinationPath>/все`, а в выбранных папках создаются относительные символические ссылки.
Исходный файл удаляется только после успешного сохранения. Примерно каждый десятый показ
берётся из `все`: выбор папок начинается пустым, новые назначения дополняют существующие.

Пути задаются через `MusicReview:SourcePath` и `MusicReview:DestinationPath` в appsettings
или переменные окружения `MusicReview__SourcePath` и `MusicReview__DestinationPath`.
В Docker Compose укажите абсолютные пути на хосте через `MUSIC_SOURCE_PATH` и
`MUSIC_DESTINATION_PATH` в `.env`; контейнер монтирует их как `/music/source` и
`/music/clean`. Каталоги не должны быть вложены друг в друга. Пользователю контейнера
нужны права на чтение и удаление в исходном каталоге и на запись в целевом. В образ
устанавливаются `ffmpeg` и `ffprobe`. Перед работой сохраните архив исходников.

Кнопка «Пропустить» оставляет файл на месте. «Удалить» с подтверждением удаляет только
неразобранный исходник; для повторно показанного файла она просто переходит дальше.
Кириллица в полях имени трека и папок автоматически переводится в латиницу, пробелы
и разделители заменяются дефисами. Итоговые имена записываются строчными буквами и соответствуют рекомендациям Foundry для
веб-ресурсов.

На странице и в окне прослушивания показывается общий прогресс разбора. Созданные папки
можно переименовывать, а при совпадении имени — объединять. При удалении папки связанные
с ней треки возвращаются в корень исходного каталога, их ссылки из остальных папок удаляются.
Если в исходном каталоге уже существует файл с таким именем, удаление папки отменяется.
